# 1. 🧠 What are we building?

We are building a simple terminal-based AI chatbot.

Our chatbot can:

* Accept user input.
* Send messages to an LLM.
* Receive AI-generated responses.
* Stream responses token by token.
* Remember previous conversation messages.

### Application Flow

```text
       👤 USER

        LLM

          |

          |

          |

```

It handles communication between our application and the model API.

### C. readline/promises

This module allows us to receive user input from the terminal using promises and `await`.

Example:


# 4. 💬 What is ChatGroq?

```javascript
const model = new ChatGroq({
    model: "openai/gpt-oss-120b",
    apiKey: process.env.GROQ_API_KEY,
});
```

Here we create an instance of `ChatGroq`.

Let's understand its properties.

| Property    | Meaning                                                            |
| ----------- | ------------------------------------------------------------------ |
| model       | Model we want to use                                               |
| apiKey      | Authentication key                                                 |
| temperature | Controls randomness                                                |
| maxTokens   | Maximum generated output tokens (provider-dependent configuration) |

**Important:** `ChatGroq` is not the actual AI model. It is the LangChain interface used to communicate with the model hosted by Groq.

# 5. 🧠 What is Message History?

```javascript
const messages = [];
```

This is one of the most important parts of our chatbot.

`messages` is an array that stores the conversation history.

Example:

```javascript
[
    {
        role: "user",
        content: "Hello"
    },
    {
        role: "assistant",
        content: "Hello! How can I help?"
    }
]
```

### Why do we need message history?

Imagine this conversation:

```text
User: My name is Mayur.

AI: Nice to meet you!

User: What is my name?

AI: Your name is Mayur.
```

How does AI know your name?

Because we send previous messages along with the latest message.

### Without Memory

```text
User: My name is Mayur.

AI: Nice to meet you!

User: What is my name?

AI: I don't know your name.
```

### With Message History

```text
messages = [

  { role: "user", content: "My name is Mayur" },

  { role: "assistant", content: "Nice to meet you!" },

  { role: "user", content: "What is my name?" }

]
```

Now the model has access to the previous conversation.

**Remember:** Your JavaScript array stores the chat history. The LLM doesn't automatically remember previous API calls.

# 7. 🔄 Understanding the Infinite While Loop

```javascript
while (true) {

    const userInp = await rl.question("Enter your Input: ");

}
```

Why `while(true)`?

Because we want our chatbot to continue accepting messages until we manually stop the program.

### Execution Flow

```text
       START
         |
         v
    Ask User Input
         |
         v
    Receive Message
         |
         v
    Generate Response
         |
         v
    Display Response
         |
         v
    Ask User Input
         |
         |
         └─────────── Repeat
```

Without this loop, the chatbot would accept only one message.

# 8. 🌊 What is Streaming?

This is a very important concept.

Normally, when we call:

```javascript
const response = await model.invoke(messages);
```

The model generates a response and returns it after generation completes.

But with streaming:

```javascript
const stream = await model.stream(messages);
```

We receive the generated response in chunks as generation progresses.

### Without Streaming

```text
User: Explain JavaScript

        WAIT...

        WAIT...

        WAIT...

AI: JavaScript is a programming language...
```

### With Streaming

```text
User: Explain JavaScript

AI: JavaScript
AI: is a
AI: programming
AI: language...
```

The exact chunk sizes are not guaranteed to be individual words or tokens.

### Streaming Flow

```text
        USER PROMPT
             |
             v
         GROQ API
             |
             v
         LLM MODEL
             |
             v
       Generate Output
             |
             v
       ┌─────────────┐
       │   CHUNK 1   │
       └─────────────┘
             |
             v
       ┌─────────────┐
       │   CHUNK 2   │
       └─────────────┘
             |
             v
       ┌─────────────┐
       │   CHUNK 3   │
       └─────────────┘
             |
             v
        COMPLETE OUTPUT
```

**Remember:** Streaming improves the perceived responsiveness of your application. It doesn't necessarily make the model generate faster.

# 9. 🔁 Understanding for await...of

```javascript
for await (const chunk of stream) {

    assistantMessage += chunk.content;

    process.stdout.write(chunk.content);

}
```

Let's break this down.

### What is for await...of?

It allows us to iterate over asynchronous data streams.

In our case, the stream produces chunks over time.

```javascript
for await (const chunk of stream)
```

It waits for the next available chunk before continuing.

### What is chunk?

A chunk is a small piece of the generated response.

Example:

```text
Chunk 1 = "JavaScript"
Chunk 2 = " is"
Chunk 3 = " powerful"
Chunk 4 = "!"
```

### What does this do?

```javascript
assistantMessage += chunk.content;
```

It combines all received chunks into one complete response.

Example:

```text
assistantMessage = ""

Chunk 1:
assistantMessage = "JavaScript"

Chunk 2:
assistantMessage = "JavaScript is"

Chunk 3:
assistantMessage = "JavaScript is powerful"
```

### What does process.stdout.write() do?

```javascript
process.stdout.write(chunk.content);
```

It prints the chunk directly to the terminal without automatically adding a new line.

This is why the response appears continuously.

# 10. 💾 Why Do We Store the Assistant Response?

```javascript

    role: "assistant",
    content: assistantMessage
});
```

Remember, we already stored the user message.

Now we store the AI response.

Why?

Because the next user message should have access to both sides of the previous conversation.

```javascript
        role: "assistant",
```

After the second conversation:

```javascript

    {
        role: "assistant",
        content: "Nice to meet you, Mayur!"
```

# 11. 🧩 Complete Code — Understanding Every Part

```javascript
import dotenv from "dotenv";

dotenv.config();

import { ChatGroq } from "@langchain/groq";

import readline from "readline/promises";

const rl = readline.createInterface({

    input: process.stdin,

    output: process.stdout,

});

const model = new ChatGroq({

    model: "openai/gpt-oss-120b",

    apiKey: process.env.GROQ_API_KEY,

});

const messages = [];

while (true) {

    const userInp = await rl.question("Enter your Input: ");

    // Store user message
    messages.push({

        role: "user",

        content: userInp,

    });

    // Request streaming response
    const stream = await model.stream(messages);

    let assistantMessage = "";

    // Receive generated chunks
    for await (const chunk of stream) {

        assistantMessage += chunk.content;

        process.stdout.write(chunk.content);

    }

    // Store complete assistant response
    messages.push({

        role: "assistant",

        content: assistantMessage

    });

    process.stdout.write("\n");

}
```

# 12. 🔬 Internal Working — What Actually Happens?

Let's connect everything we learned in Day 01 with this code.

When you enter:

```text
My name is Mayur.
```

The following process happens:

```text
        USER INPUT
             |
             v
       messages.push()
             |
             v
       model.stream()
             |
             v
       LANGCHAIN
             |
             v
       GROQ API REQUEST
             |
             v
        TOKENIZATION
             |
             v
        TRANSFORMER
             |
             v
    NEXT TOKEN PREDICTION
             |
             v
        GENERATION
             |
             v
      STREAMING CHUNKS
             |
             v
      assistantMessage
             |
             v
       messages.push()
             |
             v
       UPDATED HISTORY
```

**Important:** Tokenization, transformer processing and token generation happen on the model-serving side. Your JavaScript code communicates with the hosted model; it doesn't implement these operations itself.

# 13. ⚠️ Important Concept — Context Window

Our `messages` array keeps growing.

Example:

```javascript
[
    { role: "user", content: "Hello" },
    { role: "assistant", content: "Hi!" },
    { role: "user", content: "Explain React" },
    { role: "assistant", content: "React is..." },

    // More messages...
]
```

But LLMs have a limited context window.

**Context Window:** The maximum amount of input and generated tokens a model can handle in a single context.

As conversation grows, the model receives more historical information.

This can eventually reach the model's context limit.

Possible solutions:

1. Keep only recent messages.
2. Summarize older conversations.
3. Use a database to store conversation history.
4. Implement memory management.
